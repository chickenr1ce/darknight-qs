  • Shell root builds one slab bar per screen and owns the three floating windows. It imports no services directly.
  • Modules and windows are thin views. Modules extend ModuleBox. Both centers extend PanelShell and read one service each.
  • Services hold the mutable state. CalendarService, NotificationServer, MprisPlayers, and CavaService expose models and visibility flags. QML never touches the network directly.
  • Helpers and backends do the polling. calendar-fetch.py writes the cache file. calendar-clock.py prints zone times to stdout for the collector. QML reads the cache through FileView.

Read order, left to right. Shell passes screen and anchor down. Services push state up. Clock and the bell close each other through the other service. Toast popups read both services, and tray shares focus logic with the notification server.

Risks

  • Coupled closers. Two panels enforce one open panel by writing to each other. A third panel triples the links. A shared closer removes the mesh.
  • All or nothing polls. One dead calendar fails the whole 15 minute poll by design. Hiding the calendar is the escape hatch. Per calendar isolation stays out of scope until users ask.
  • Focus is best effort. Outside click always dismisses. Escape needs panel focus. Fast re toggle inside 300 ms can swallow the open. Tests should encode this limit.
  • Cache loss looks like no data. The stale marker covers failed polls. It does not cover a wiped cache dir. State dir storage or a startup seed closes the gap.

Open questions

  • Q1. Which CalendarCenter view splits first, and what stays shared through PanelShell?
  • Q2. Where does the shared Hyprland focus helper live so Tray and NotificationServer both use it?
  • Q3. Does the last good events cache move to state dir, or does the cache dir tradeoff stand?
  • Q4. What headless check guards panel placement and stale rendering without a live compositor?

Top recommendation

Deepen the panel open/close state machine

Three singletons copy the same state machine, and the one-panel rule is an N² mesh that already leaks (toasts render over the cava panel). It is the only candidate where a new feature, the next panel, pays the leverage dividend immediately; it deepens recorded finding F9 instead of patching it, and ADR 0001's composition constraint tells us exactly where the seam goes.
