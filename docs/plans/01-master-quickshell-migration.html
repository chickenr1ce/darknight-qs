01

Scope & Decisions

The goal is deliberate improvement — in form and function. Parity with the current Waybar bar is the translation baseline: modules, layout, theme and interactions are reproduced first so nothing is lost, then each module is improved where Quickshell does it better (native services over shell-outs, accurate text elision, event-driven state, true centering). One codebase, two outputs: DP-1 full, DP-2 minimal.

Accepted decisions DEC

  • Goal: deliberate improvement in form and function. Waybar parity is the translation baseline; improvements over waybar are the point, logged per deviation.
  • Entry: ~/.config/quickshell/shell.qml (Quickshell default dir).
  • One codebase, instanced per-monitor via Variants + Quickshell.screens; DP-1 full bar, DP-2 clock + workspaces only.
  • Audio: native Quickshell.Services.Pipewire (matches wireplumber).
  • Audio sink cycle JadeAudio → AB13X Dongle → Creative Pebble V3 reimplemented in QML, replacing toggle_audio.sh.
  • Cava: real QML rectangles (not unicode blocks) via cava subprocess raw output. Deferred to Phase 7 (2026-08-23) — not required for parity.
  • Notifications: native Quickshell.Services.Notifications daemon replaces swaync, removing the external dependency; the existing swaync-client shell-out is migrated (Q1).
  • Power menu: keep rofi script ~/.config/rofi/powermenu/type-1/powermenu.sh.

Assumptions ASS

  • Installed QML modules cover every requirement – verified: Hyprland, Mpris, Pipewire, SystemTray, Io, Wayland, Notifications, IdleInhibitor.
  • Comfortable editing QML; learning curve is the main cost, not capability gaps.
  • Waybar remains installed in parallel until Quickshell is validated; cutover is final.
Ground rule: preserve exact palette values and waybar spacing truth as the baseline; improvements deviate deliberately and are reconciled in the deviation log, not in prose.
Δ Deviation log – observed in working config 15 findings · updated 2026-08-23

  • D2 · Multi-monitor uses Quickshell.screens + modelData / monitorName (Variants model), not the plan’s conceptual qs.monitor.
  • D3 · Right cluster gated by idPanelWindow.monitorName === "DP-1"; left Clock + Workspaces on every monitor.
  • D4 · Cpu uses Process running bash -c "grep '^cpu ' /proc/stat" + StdioCollector, not plan’s FileView. Equivalent.
  • D5 · Audio sink cycle uses wpctl set-default via Process (plan fallback R2), not pure Pipewire API. Works against three named sinks.
  • D6 · Mpris module is named Media.qml, not Mpris.qml.
  • D7 · Notifications toggles only (swaync-client -t -sw); plan’s count badge (-swb) not yet. This swaync-based solution is deprecated: superseded by the Q1 decision — swap out for native Quickshell.Services.Notifications.
  • D8 · Workspaces.qml built and wired (was stub). Persistent 5 per monitor via Repeater, monitor split DP-1 → 1–5 / DP-2 → 6–10; active = lavender + secondary bg, urgent = red, hover = text. Cava deferred to Phase 7 (2026-08-23). Update: Tray.qml has since been built and wired — see docs/tray-module.md.
  • D9 · Font size is 14px, not waybar’s 16px. Globals.fontPixelSize = 14 chosen for barHeight 28; deliberate, logged per ground rule.
  • D10 · ModuleBox sizing bounds & properties. minWidth and maxWidth constraints are computed directly in implicitWidth to keep the component layout-agnostic. enableMouseArea (default true) disables the box-level click pane for modules with their own buttons (Workspaces); horizontalPadding supports custom tightening.
  • D11 · Hyprland ≥ 0.56 IPC is Lua-evaluated. Legacy dispatch strings fail: quickshell’s Hyprland.dispatch("workspace N") errors with ')' expected (same for hyprctl dispatch). Working form used in Workspaces.qml: Hyprland.dispatch("hl.dsp.focus({ workspace = N })"). Revisit when quickshell ships native 0.56 IPC support.
  • D12 · Dynamic content stability & native elision. Media.qml is backed by services/MprisPlayers.qml singleton and caps width with maxWidth: 360 + native Qt elide: Text.ElideRight. Cpu.qml prevents 1-digit vs 2-digit jitter symmetrically via minWidth: 62.
  • D13 · Unified slab replaces floating modules (landed 2026-08-24, ECO-HY3a). A single Colors.background surface spans the bar (slabRadius: 9); modules lose their own backgrounds and become transparent hover regions. Supersedes the waybar #module per-box styling translated in Phase 1. Spec: docs/plans/02-phase-6a-unified-slab.html.
  • D14 · Motion system added (landed 2026-08-24, ECO-HY3a). Pill hover tint (inset 2px) + centered expanding lavender underline at 140ms; press-scale + release pulse 120ms; Workspaces and Tray scale only the clicked pill/icon. Cluster hairlines flank the center region. No waybar counterpart — deliberate improvement per ground rule.
  • D15 · Hero element iteration (landed 2026-08-24, ECO-HY3a). Living gradient tested on active workspace pill and rejected as visually noisy; reverted to solid backgroundSecondary with lavender text. Hero ownership deferred to Cava audio visualizer (Phase 7).
  • D16 · Hairlines & Media refinement (landed 2026-08-24, ECO-HY3a). Hairlines upgraded to 2px @ 50% opacity with dynamic collision guards to prevent module overlap; Media module unified to transparent slab with text-color playback indication.

Target File Structure

Small tree of QML files – each module isolated so a typo in Audio.qml doesn’t take down the clock. shell.qml wires them into per-monitor PanelWindows.

~/.config/quickshell – as-built
~/.config/quickshell/ ├── AGENTS.md # QML conventions (IDs, layout host pattern, sizing & stability) ├── bar-switch # waybar ↔ quickshell toggle script ├── shell.qml # entry: Variants per monitor → PanelWindow + WlrLayerShell ├── config/ │ ├── Colors.qml # color singleton (from colors/colors.css) │ ├── Globals.qml # height, spacing, bar geometry │ └── qmldir # singleton declarations for Colors & Globals ├── services/ │ ├── MprisPlayers.qml # MPRIS player tracking singleton & cycling │ └── qmldir # singleton declaration for MprisPlayers ├── components/ │ ├── ModuleBox.qml # layout-agnostic slab region host: min/maxWidth, hover │ tint + underline (D13/D14) │ ├── PressFeedback.qml # shared release pulse + hover underline (D14) │ └── PressScale.qml # shared press-squash driver, OutQuad/OutBack (D14) └── modules/ ├── Clock.qml left (Timer + Text) ● done ├── Workspaces.qml left (Repeater · Hyprland, Lua dispatch D11) ● done ├── ActiveWindow.qml center (Hyprland rawEvent + hyprctl seed, anchored center) ● done ├── Media.qml right (MprisPlayers singleton + native elide D12) ● done [plan: Mpris.qml] ├── Cpu.qml right (/proc/stat via Process + minWidth: 62 D12) ● done ├── Audio.qml right (Pipewire default sink + wpctl cycle + scroll volume) ● done ├── Notifications.qml right (native NotificationServer singleton + bell/badge/DND per Q1 — no swaync) ● done ├── Tray.qml right (Quickshell.Services.SystemTray StatusNotifier items + icon ≈14) ● done └── PowerMenu.qml right (Process → rofi powermenu script) ● done # DEFERRED to Phase 7 (2026-08-23): Cava.qml — see modules/new-modules backlog
Why split? Quickshell compiles each QML file separately; isolating modules makes acceptance checks per-module and keeps the bar resilient.

Waybar uses two separate bar objects; Quickshell uses one Variants block that instantiates the panel once per connected monitor. Hotplug is automatic – Variants recreates instances when the monitor set changes.

shell.qml – actual
//@ pragma UseQApplication
pragma ComponentBehavior: Bound

import QtQuick
import QtQuick.Layouts
import Quickshell
import qs.config
import qs.modules

// One PanelWindow per connected screen (Variants over Quickshell.screens).
ShellRoot {
  id: root

  Variants {
    id: idScreenVariants
    model: Quickshell.screens

    // qmllint disable uncreatable-type
    PanelWindow {
      id: idPanelWindow

      required property ShellScreen modelData
      property string monitorName: modelData.name

      screen: modelData

      implicitHeight: Globals.barHeight + Globals.moduleMargin
      color: "transparent"

      anchors {
        top: true
        left: true
        right: true
      }

      // Unified slab — one full-width surface behind all regions (Phase 6a, D-01).
      Rectangle {
        id: idSlab

        anchors {
          top: parent.top
          left: parent.left
          right: parent.right
          topMargin: Globals.moduleMargin
          leftMargin: Globals.horizontalBarMargin
          rightMargin: Globals.horizontalBarMargin
        }

        height: Globals.barHeight
        radius: Globals.slabRadius
        color: Colors.background

        // Cluster hairlines flanking the center region only (D-07),
        // with collision/empty guards against side clusters.
      }

      RowLayout {
        id: idBarLayout

        spacing: Globals.spacing

        anchors {
          fill: parent
          leftMargin: Globals.slabInset
          rightMargin: Globals.slabInset
          topMargin: Globals.moduleMargin
        }

        // Left cluster
        Clock {}
        Workspaces {
          monitorName: idPanelWindow.monitorName
        }
        Tray {
          visible: idPanelWindow.monitorName === "DP-1"
        }

        Item {
          id: idSpacer
          Layout.fillWidth: true
        }

        // Right cluster (full bar only)
        Media {
          visible: idPanelWindow.monitorName === "DP-1"
        }
        Audio {
          visible: idPanelWindow.monitorName === "DP-1"
        }
        Cpu {
          visible: idPanelWindow.monitorName === "DP-1"
        }
        Notifications {
          visible: idPanelWindow.monitorName === "DP-1"
        }

        PowerMenu {
          visible: idPanelWindow.monitorName === "DP-1"
        }
      }

      // Center module — anchored to the bar itself so it stays in the
      // exact horizontal center regardless of side-cluster widths
      // (mirrors waybar's absolutely-positioned center section).
      ActiveWindow {
        anchors {
          horizontalCenter: parent.horizontalCenter
          verticalCenter: parent.verticalCenter
          verticalCenterOffset: Globals.moduleMargin / 2
        }
      }
    }
  }
}

09

Risks & Mitigations

R1

QML learning curve · JSON+CSS → QML

Risk: Waybar is JSON+CSS; Quickshell is QML. Mitigation: build module-by-module with per-phase validation; reuse ModuleBox so styling is written once.

R2

Pipewire property names · API drift

Risk: Exact sink/volume API may differ from assumption. Mitigation: inspect /usr/lib/qt6/qml/Quickshell/Services/Pipewire/quickshell-service-pipewire.qmltypes before Audio.qml; fallback to wpctl via Process if needed.

R3

cava raw parsing · framing

Risk: Raw 16-bit framing must match subprocess config. Mitigation: reuse framing logic proven in cava_module.py (chunk = 2 × bars, struct unpack).

R4

Theme fidelity · GTK → QML

Risk: GTK CSS nuances (tray icon effects) may not translate 1:1. Mitigation: pixel-compare during Phase 6; accept minor tray-effect differences.

R5

swaync coupling · external dep

Risk: swaync adds one external dependency. Resolution (Q1): replace with native Quickshell.Services.Notifications, removing the dependency; until the migration lands, current behaviour remains low risk.

Open Questions

Q1 – Keep swaync or switch to Quickshell’s native notification daemon? — Decided: switch to native.
