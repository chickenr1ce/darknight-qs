# CONTEXT.md

## Glossary

* Calendar panel: the `windows/CalendarCenter.qml` floating window plus `services/CalendarService.qml` state. Trigger is the `modules/Clock.qml` module in the bar left cluster.
* Under its trigger: every floating panel opens on the clicked monitor directly below its trigger module, pixel aligned, not side aligned. Calendar follows Clock, notification center follows the bell, cava follows its bars, future panels follow their own modules.
* Agenda: selected day event list under the month grid. Driven by existing `selectedIso`. Dots mark days with events.
* Inline zone edit: add and remove world clock zones inside the calendar panel. No separate settings window. Persisted to a file so zones survive restart.
* Last good plus stale: offline pattern shared by events and zones. Keep the last fetched file, show a stale marker from file age instead of blank.
* Backend: secret iCal URL plus curl first, `gcalcli` later if multi calendar search or true freshness matters. Per calendar URL, token is the URL.
* Full feed plus per view expansion: poll the full ICS feed, cache locally, expand recurrences only for the rendered 42 days. Month shift never triggers network, any year renders from cache.
* Cava panel: the `windows/CavaCenter.qml` floating window plus `services/CavaService.qml` state. Trigger is the `modules/Cava.qml` visualizer in the bar right cluster, primary-only.
* Cava styles: six modes (Bars, Mirrored, Wave, Wave Blocks, Ribbon, Ribbon Blocks). Scroll on the bars cycles the mode, the panel dropdown picks it directly.
* Cava tuning: sensitivity, auto sensitivity, bar count, max height. Persisted to the state file so settings survive restart. Changes that affect the engine restart the cava process. Bars flatten after 600ms without frames.
* Panels registry: the `services/Panels.qml` singleton owning the one-panel rule. Its `panels` list holds the four services' `PanelState` instances; opening one closes every other entry and `anyOpen` derives from the list. Triggers call its toggle functions instead of writing each other's services; each service keeps its own state by composing `services/PanelState.qml`. `Panels.anyOpen` hides toasts while any panel is open.
* Hyprland focus: the `services/HyprlandFocus.qml` singleton owning focus-match plus cursor save, focus, and restore. Concurrent clicks queue behind the in-flight read; dispatch routes through an injectable function for testing. An empty toplevel list retries for about 3s, a hung cursor snapshot focuses without restore and warns, match failures warn. Class matching reads the Hyprland IPC object and the Wayland `appId`; the IPC object is empty under Hyprland's Lua IPC, so the `appId` is the source that works there. A reverse-DNS token matches on its last segment, so it cannot collapse to a generic prefix like `org`. A request waits while a panel is mid-close (`PanelGrab.closing`), because the compositor restores the previously focused window when the panel's grab releases and would otherwise override the new focus.
* Notification center: the `windows/NotificationCenter.qml` floating window plus `services/NotificationServer.qml` state. Groups collapse by app with a loud header, dot plus uppercase name plus count plus quiet Clear. Rows carry a 3px rail in the app color, critical rows use danger red with a dark red wash. The list scrolls inside a capped height and expanding a group glides it into view. Opening the center clears banners and keeps history.
* Notification toasts: the `components/NotificationToast.qml` banners. At most 6 show, oldest drops first. Only critical toasts stick, a 0 timeout clamps to 30s, hover pauses decay. DND or an open center suppresses new toasts. The View action focuses the app through HyprlandFocus, then invokes.
* Notification collection: `services/NotificationServer.qml` exposes one `notifications` list. `groups` (grouped by app), `toasts`, and `unreadCount` are derived from it; the raw DBus collection stays private. `isCritical(notification)` owns the urgency check and its null guard; `sendReply(notification, text)` owns the read-resident-before-send order.
* State file module: `services/StateFile.qml` owns XDG state and cache path resolution, the watch plus reload plus parse hook, a `save()` equality guard so an unchanged write queues no extra poll, and a `loading` flag. Pure parsers live in `services/StateParsers.js`. Calendar zones, hidden calendars, and cava settings compose it.
* Primary monitor: `Globals.primaryMonitor` plus `onPrimaryMonitor()` is the single full-bar rule. `Globals.screensByPosition` orders `Quickshell.screens` by x, then y, then name; the resolved primary is the persisted `MonitorService` override (`monitor-settings`) when it names a connected screen, otherwise the first screen. Full-bar modules declare `monitorName` and compose the check with their own content rule; the shell passes the monitor name instead of setting visibility.
* Workspace split: each monitor owns a contiguous block of `MonitorService.workspacesPerMonitor` workspaces, ordered by `MonitorService.orderedMonitors` (primary first, then `Globals.screensByPosition`). `MonitorService.firstWorkspaceFor(monitorName)` starts the primary at 1 and each following monitor at the previous end plus one; an empty or unknown name yields 1. The count (default 5, 1–20) is editable in Settings → Monitors and persists in `monitor-settings`.
* Power panel: the `windows/PowerCenter.qml` floating window plus `services/PowerService.qml` state. Trigger is the `modules/PowerMenu.qml` power glyph in the bar right cluster, primary-only. One flat monochrome list; Lock fires at once through the hyprlock, betterlockscreen, i3lock chain, the other five arm and need one confirm.
* Audio outputs: `services/AudioService.qml` discovers every real Pipewire sink at runtime (a sink, not a stream, with an audio object), so the dashboard volume list and the bar's click cycle work on any machine. The user curates the detected outputs in Settings → Audio: show or hide each from the dashboard and order the list. Curation persists to the `audio-outputs` state file (hidden keys, order) behind the `StateFile` load guard, keyed by the Pipewire node name. Hidden outputs drop from both the dashboard and the bar cycle; an output the user has not curated appends after the saved order, sorted by label. Replaces the per-device allowlist the shell was migrated with.
* Reduced motion: the `Globals.reducedMotion` switch gating every panel animation (rows, footer, shared `PanelShell` entrance, `PressScale`) to instant. Off by default.
* Font picker: the Settings → Fonts section (`windows/FontsSettingsView.qml`) choosing the Interface (`Globals.uiFontFamily`), Bar (`Globals.fontFamily`), and Icons (`Globals.iconFontFamily`) families. `services/FontService.qml` enumerates `Qt.fontFamilies()`, restricts the icon role to Nerd Font families, writes the shared `Globals` roles, and persists the three picks to the `font-settings` state file behind the `StateFile` load guard. A saved family that is no longer installed keeps the shipped default. Every picker starts collapsed and reveals an in-flow search field plus a capped result list, because the panel clips anything outside its layout.
* Settings tab: the `windows/SettingsView.qml` page inside the dashboard's Settings tab, opened from the dashboard gear or the dashboard Theme block. Search sits above the section rail; matching options render in the card body while the rail narrows to matching sections, with a no-match note on empty results. It edits the same service state as the quick panels, so changes mirror both ways. Replaces the Hyprland-managed window (ADR 0012, supersedes ADR 0007).
* Dashboard tabs: the `windows/DashboardTabs.qml` page row inside the dashboard card, driven by `DashboardService.activeTab` and switched by `DashboardService.selectTab(key)`. Dashboard is the default page; Media, Performance, and Workspaces show the "Coming soon" placeholder until their pages land. Settings is not a row tab: the header gear to the right of the row calls `DashboardService.openSettings`, which selects the hidden Settings page without closing the card and lights the gear accent. `DashboardService.openSettings("theme")` deep-links the Theme section.
* Dashboard: the `windows/DashboardCenter.qml` attached card plus `services/DashboardService.qml` state. Trigger is the bar center title in `modules/ActiveWindow.qml`. It opens on the clicked screen as a centered card under the bar and lives outside `services/Panels.qml`, so a quick panel opens beside it instead of replacing it (ADR 0008).
* Dashboard junction: the meeting surface where the attached dashboard card's top edge joins the bar's bottom edge. Shaped as a concave fillet, material added in the reflex corner, so bar and card read as one surface.
* Junction radius: the fillet radius of the dashboard junction. Lives on `DashboardService.junctionRadius`, user adjustable 0 to `Globals.junctionRadiusMax` (32) from the Settings Dashboard section (where it is labelled "Seam radius") and persisted to the `dashboard-junction` state file behind the `StateFile` load guard, where 0 renders the square join. The card window widens to `dashboardWidth + 2 × junction radius`; the card body stays `dashboardWidth`.
* Quick panel mirror: the rule that the settings view and the quick panels bind the same service properties for Cava, Calendar, DND and reduced motion. A change on either side shows on the other at once, and no state is duplicated.
* Spotify Connect device switch: the device list in the dashboard player block (`windows/DashboardPlayerBlock.qml`), one chip per real Connect device from `services/SpotifyService.qml`. The active device is highlighted and clicking another moves the session there. The backend is `scripts/spotify-connect.py`; the token is a shell-owned PKCE credential written by `scripts/spotify-auth.py` (ADR 0009, setup in `docs/spotify-connect.md`). A missing token hides the row.
* Player cover art: the dashboard player block's 86px art slot binds `MprisPlayer.trackArtUrl` through a `ClippingRectangle`, cropping non-square art and falling back to the flat card fill plus a music glyph when no art is loaded. Clicking it closes the dashboard and focuses the Spotify window through `HyprlandFocus`.
* Weather block: the dashboard weather block (`windows/DashboardWeatherBlock.qml`) showing city, temperature, condition glyph, rain probability, and day high and low from `services/WeatherService.qml`. The source is Open-Meteo with no key, polled every 30 minutes and on dashboard open; a reading older than 60 minutes or a failed poll marks the city label stale while the last values stay. The last good payload caches at `weather.json` (setup in `docs/weather.md`).
* City search: the Settings Weather section (`windows/WeatherSettingsView.qml`) that searches the Open-Meteo geocoding API and writes the picked city to `weather-location`. Searchable under the `City` and `Location` labels; selecting a result repolls at once.
* Theme: an omarchy v4 (`quattro`) theme directory installed under the theme root. Its `colors.toml` is the palette and its `backgrounds/` directory holds images. Read as data, never executed (ADR 0010, ADR 0011).
* Palette: the color role set resolved from the active theme's `colors.toml` and mapped onto `config/Colors.qml` tokens. The word wallpaper is never used for this.
* Theme root: `~/.local/share/quickshell/themes`, the quickshell-owned directory the catalog scans and `qs-theme install` writes to. Not an omarchy path.
* Bundled theme: the one theme the repository ships, `darknight`, under `assets/themes/`, seeded into the theme root by `scripts/install.sh`. It is the hardcoded `config/Colors.qml` fallback made a real theme, with two backgrounds, so the catalog is never empty on a fresh install.
* Default theme: `ThemeService.defaultThemeName` (`darknight`), selected once the catalog is ready when the state file holds no saved selection; a state file that does not parse as a JSON object counts as no selection, so a corrupt file heals to the default. A selection the user saved, even one whose theme left the catalog, is not overridden.
* Catalog: the themes discovered in the theme root, listed by display name, each carrying a preview swatch strip read from its `colors.toml`.
* Background: an image a theme ships under its `backgrounds/` directory. The user picks one per theme; the choice is remembered per theme and applied with awww. A new pick queues behind the running awww rather than restarting it, so a superseded process's non-zero exit is not read as a failure.
* Surface: a `config/Colors.qml` role group (panel, card, border, text) derived from palette roles when the theme has no exact key for it.
* Theme switch: applying a catalog theme so the palette, the bar, the rendered desktop files, and the remembered background all change together. A fresh install selects the bundled darknight theme, so the default palette matching the hardcoded `config/Colors.qml` fallback is written only when the bundle is absent or a saved theme left the catalog, keeping the bar and the desktop files in agreement.
* qs-theme: the CLI (`install`, `remove`, `list`, `current`, `set`, `background`, `add-background`, `remove-background`), a thin client over shell IPC except that `install`, `remove`, `add-background`, and `remove-background` write the theme root themselves.
* Desktop retint: `scripts/render-theme.sh` substitutes the active palette into the repo-owned templates under `assets/templates/` and writes `~/.config/hypr/theme.lua`, `~/.config/kitty/theme.conf`, `~/.config/hypr/hyprlock/colors.conf`, `~/.config/starship.toml`, and `~/.config/yazi/theme.toml`. `ThemeService` runs it on every palette load and change through a `Process`. Borders honor the theme's `hyprland_*_border` keys when present and otherwise derive from `accent`. Starship and yazi have no include directive, so the renderer owns their whole config files (yazi's replaces the static flavor reference); the other three are wired in by user-added include or source lines (`docs/theme-desktop-setup.md`). The renderer writes a file only when the bytes change, and it never reads or evaluates a theme directory.
