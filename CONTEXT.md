# CONTEXT.md

## Glossary

* Calendar panel: the `windows/CalendarCenter.qml` floating window plus `services/CalendarService.qml` state. Trigger is the `modules/Clock.qml` module in the bar left cluster.
* Under its trigger: every floating panel opens on the clicked monitor directly below its trigger module, pixel aligned, not side aligned. Calendar follows Clock, notification center follows the bell, cava follows its bars, future panels follow their own modules.
* Agenda: selected day event list under the month grid. Driven by existing `selectedIso`. Dots mark days with events.
* Inline zone edit: add and remove world clock zones inside the calendar panel. No separate settings window. Persisted to a file so zones survive restart.
* Last good plus stale: offline pattern shared by events and zones. Keep the last fetched file, show a stale marker from file age instead of blank.
* Backend: secret iCal URL plus curl first, `gcalcli` later if multi calendar search or true freshness matters. Per calendar URL, token is the URL.
* Full feed plus per view expansion: poll the full ICS feed, cache locally, expand recurrences only for the rendered 42 days. Month shift never triggers network, any year renders from cache.
* Cava panel: the `windows/CavaCenter.qml` floating window plus `services/CavaService.qml` state. Trigger is the `modules/Cava.qml` visualizer in the bar right cluster, primary-only.
* Cava styles: six modes (Bars, Mirrored, Wave, Wave Blocks, Ribbon, Ribbon Blocks). Scroll on the bars cycles the mode, the panel dropdown picks it directly.
* Cava tuning: sensitivity, auto sensitivity, bar count, max height. Persisted to the state file so settings survive restart. Changes that affect the engine restart the cava process. Bars flatten after 600ms without frames.
* Panels registry: the `services/Panels.qml` singleton owning the one-panel rule. Its `panels` list holds the four services' `PanelState` instances; opening one closes every other entry and `anyOpen` derives from the list. Triggers call `Panels.toggleAt(panel, screen, x)` with the service's `panelState`; each service exposes `panelState` and composes `services/PanelState.qml`, and Power, Calendar, and Notification also expose `barAnchor` and compose `services/BarAnchor.qml`, so an IPC toggle runs the same trigger path a click does. The quick-panel windows hand `PanelShell` that `panel`. `Panels.anyOpen` hides toasts while any panel is open, and power arming resets when its own panel opens or closes.
* Hyprland focus: the `services/HyprlandFocus.qml` singleton owning focus-match plus cursor save, focus, and restore. Concurrent clicks queue behind the in-flight read; dispatch routes through an injectable function for testing. An empty toplevel list retries for about 3s, a hung cursor snapshot focuses without restore and warns, match failures warn. Class matching reads the Hyprland IPC object and the Wayland `appId`; the IPC object is empty under Hyprland's Lua IPC, so the `appId` is the source that works there. A reverse-DNS token matches on its last segment, so it cannot collapse to a generic prefix like `org`. A request waits while a panel is mid-close (`PanelGrab.closing`), because the compositor restores the previously focused window when the panel's grab releases and would otherwise override the new focus.
* Notification center: the `windows/NotificationCenter.qml` floating window plus `services/NotificationServer.qml` state. Groups collapse by app with a loud header, dot plus uppercase name plus count plus quiet Clear. Rows carry a 3px rail in the app color, critical rows use danger red with a dark red wash. The list scrolls inside a capped height and expanding a group glides it into view. Opening the center clears banners and keeps history.
* Notification toasts: the `components/NotificationToast.qml` banners. At most 6 show, oldest drops first. Only critical toasts stick, a 0 timeout clamps to 30s, hover pauses decay. DND or an open center suppresses new toasts. The View action focuses the app through HyprlandFocus, then invokes.
* Notification collection: `services/NotificationServer.qml` exposes one `notifications` list. `groups` (grouped by app), `toasts`, and `unreadCount` are derived from it; the raw DBus collection stays private. `isCritical(notification)` owns the urgency check and its null guard; `sendReply(notification, text)` owns the read-resident-before-send order.
* State file module: `services/StateFile.qml` owns XDG state and cache path resolution, the watch plus reload plus parse hook, a `save()` equality guard so an unchanged write queues no extra poll, and a `loading` flag. Pure parsers live in `services/StateParsers.js`. It is composed by cava settings, audio outputs, MPRIS apps, monitor settings, bar visibility, bar margins, font roles, the dashboard junction, calendar zones and hidden calendars, the weather cache, and the theme selection. StateFile itself refuses a save while the file is loading or before the first load (cache files excepted), and `saveJson(payload)` writes a JSON payload, so no writer can overwrite a file it has not read yet.
* Service logic module: the `.pragma library` JS file beside a service holding its pure functions — `services/WeatherLogic.js`, `SpotifyLogic.js`, `MprisLogic.js`, `MonitorLogic.js`, `SystemLogic.js`, `AudioLogic.js`, alongside the shared `services/StateParsers.js` and `ThemeParsers.js`. The service imports it and keeps its public function names as one-line delegates, passing service state into a binding so it stays reactive; the tests run the real file under node through `tests/qmljs.js`.
* Primary monitor: `Globals.primaryMonitor` plus `onPrimaryMonitor()` is the single full-bar rule. `Globals.screensByPosition` orders `Quickshell.screens` by x, then y, then name; the resolved primary is the persisted `MonitorService` override (`monitor-settings`) when it names a connected screen, otherwise the first screen. Full-bar modules declare `monitorName` and compose the check with their own content rule; the shell passes the monitor name instead of setting visibility.
* Workspace split: each monitor owns a contiguous block of `MonitorService.workspacesPerMonitor` workspaces, ordered by `MonitorService.orderedMonitors` (primary first, then `Globals.screensByPosition`). `MonitorService.firstWorkspaceFor(monitorName)` starts the primary at 1 and each following monitor at the previous end plus one; an empty or unknown name yields 1. The count (default 5, 1–20) is editable in Settings → Monitors and persists in `monitor-settings`.
* Display toggle: Settings → Monitors turns an output off or back on through Hyprland's Lua monitor API (`hyprctl eval 'hl.monitor({…})'`), not `hyprctl keyword`, which the Lua config parser rejects. `MonitorService` polls `hyprctl monitors all -j`; the `all` list keeps a disabled output and its geometry, so a re-enable restores its mode and position instead of a guessed preferred mode. The list works even when the shell starts with a display already off, and the last display stays on. ADR 0016.
* Power panel: the `windows/PowerCenter.qml` floating window plus `services/PowerService.qml` state. Trigger is the `modules/PowerMenu.qml` power glyph in the bar right cluster, primary-only. One flat monochrome list; Lock fires at once through the hyprlock, betterlockscreen, i3lock chain, the other five arm and need one confirm.
* Audio outputs: `services/AudioService.qml` discovers every real Pipewire sink at runtime (a sink, not a stream, with an audio object), so the dashboard volume list and the bar's click cycle work on any machine. The user curates the detected outputs in Settings → Audio: show or hide each from the dashboard and order the list. Curation persists to the `audio-outputs` state file (hidden keys, order) behind the `StateFile` load guard, keyed by the Pipewire node name. Hidden outputs drop from both the dashboard and the bar cycle; an output the user has not curated appends after the saved order, sorted by label. Replaces the per-device allowlist the shell was migrated with.
* Reduced motion: the `Globals.reducedMotion` switch gating every panel animation (rows, footer, shared `PanelShell` entrance, `PressScale`) to instant. Off by default.
* Font picker: the Settings → Fonts section (`windows/FontsSettingsView.qml`) choosing the Interface (`Globals.uiFontFamily`), Bar (`Globals.fontFamily`), and Icons (`Globals.iconFontFamily`) families. `services/FontService.qml` enumerates `Qt.fontFamilies()`, restricts the icon role to Nerd Font families, writes the shared `Globals` roles, and persists the three picks to the `font-settings` state file behind the `StateFile` load guard. A saved family that is no longer installed keeps the shipped default. Every picker starts collapsed and reveals an in-flow search field plus a capped result list, because the panel clips anything outside its layout.
* Bar margins: the Settings → Layout section (`windows/LayoutSettingsView.qml`) sets the bar's outer top and side margins. The values live as writable `Globals.barTopMargin` (0–`barTopMarginMax`, default 4) and `Globals.barSideMargin` (0–`barSideMarginMax`, default 10); `services/BarMarginService.qml` clamps them and persists to the `bar-margins` state file behind the `StateFile` load guard. The shell slab, the bar window height, the panel edge clamp, and the notification popup offset all follow the tokens, so changing a margin moves the bar, its panels, and its toasts together.
* Settings tab: the `windows/SettingsView.qml` page inside the dashboard's Settings tab, opened from the dashboard gear or the dashboard Theme block. Search sits above the section rail; matching options render in the card body while the rail narrows to matching sections, with a no-match note on empty results. It edits the same service state as the quick panels, so changes mirror both ways. Replaces the Hyprland-managed window (ADR 0012, supersedes ADR 0007).
* Dashboard tabs: the `windows/DashboardTabs.qml` page row inside the dashboard card, driven by `DashboardService.activeTab` and switched by `DashboardService.selectTab(key)`. Dashboard is the default page; Apps (formerly Media) hosts the launcher list; Performance and Workspaces show the "Coming soon" placeholder until their pages land. Settings is not a row tab: the header gear to the right of the row calls `DashboardService.openSettings`, which selects the hidden Settings page without closing the card and lights the gear accent. `DashboardService.openSettings("theme")` deep-links the Theme section.
* App launcher: the `windows/DashboardAppsView.qml` list plus `services/AppService.qml` state and `services/AppLogic.js` pure logic, shown as the dashboard's Apps tab (the former Media placeholder). An empty query shows Pinned, then Recent (unpinned, at most 4), then All apps A–Z; a query shows one ranked list with the matched letters highlighted, and no match offers a Run "query" row. Entry points are the `dashboard apps` IPC target (the Super bind) and the tab row; the bar title still opens the Dashboard page. ADR 0018.
* Inline actions: the launcher controls swapped in on the selected or hovered running row: Focus, Kill, Pin/Unpin, and `⋯` (the context menu). They replace the running dot, window count, and pin star at rest; Focus and Kill stay laid out but dim and inert when the app has no window, so the row never reflows.
* Kill: closing every window matched to an app through its Wayland handle (`wayland.close()`), a graceful close with no confirm. Matching is exact (`AppLogic.windowMatches`), not the loose `HyprlandFocus.classMatches`; apps may still prompt to save, and there is no force-kill.
* Workspace shortcut: the launcher's absolute workspace number. Ctrl+N opens on workspace N and Ctrl+0 on workspace 10, available while N is within `workspacesPerMonitor × enabled monitors` (the anchor block until the monitor list loads); the context menu's "Open on workspace" submenu lists every enabled monitor's block and dispatches each item's absolute workspace through `hl.dsp.exec_cmd(cmd, { workspace = N })` with each argv element shell-quoted.
* AppIcon: `components/AppIcon.qml`, the shared app artwork: the resolved icon, else a letter tile tinted with `Colors.appColor(name)` and painted with the theme-independent `Colors.tileInk`, else a caller glyph tile. The launcher row and the Settings hidden-apps row compose it.
* Dashboard: the `windows/DashboardCenter.qml` attached card plus `services/DashboardService.qml` state. Trigger is the bar center title in `modules/ActiveWindow.qml`. It opens on the clicked screen as a centered card under the bar and lives outside `services/Panels.qml`, so a quick panel opens beside it instead of replacing it (ADR 0008).
* Dashboard junction: the meeting surface where the attached dashboard card's top edge joins the bar's bottom edge. Shaped as a concave fillet, material added in the reflex corner, so bar and card read as one surface.
* Junction radius: the fillet radius of the dashboard junction. Lives on `DashboardService.junctionRadius`, user adjustable 0 to `Globals.junctionRadiusMax` (32) from the Settings Dashboard section (where it is labelled "Seam radius") and persisted to the `dashboard-junction` state file behind the `StateFile` load guard, where 0 renders the square join. The card window widens to `dashboardWidth + 2 × junction radius`; the card body stays `dashboardWidth`.
* Quick panel mirror: the rule that the settings view and the quick panels bind the same service properties for Cava, Calendar, DND and reduced motion. A change on either side shows on the other at once, and no state is duplicated.
* Spotify Connect device switch: the device list in the dashboard player block (`windows/DashboardPlayerBlock.qml`), one chip per real Connect device from `services/SpotifyService.qml`. The active device is highlighted and clicking another moves the session there. The backend is `scripts/spotify-connect.py`; the token is a shell-owned PKCE credential written by `scripts/spotify-auth.py` (ADR 0009, setup in `docs/user/spotify-connect.md`). A missing token hides the row.
* Player cover art: the dashboard player block's 86px art slot binds `MprisPlayer.trackArtUrl` through a `ClippingRectangle`, cropping non-square art and falling back to the flat card fill plus a music glyph when no art is loaded. Clicking it closes the dashboard and focuses the Spotify window through `HyprlandFocus`.
* MPRIS app filter: `services/MprisPlayers.qml` folds every discovered player into an app map keyed by `desktopEntry` (else identity, else dbus name), seeded so browser entries default to hidden, and persists the map to the `mpris-players` state file. `playerList` filters through that map, so the dashboard player block and the bar Media module share one allow list; `seenPlayers` feeds the Settings Media section (`windows/MediaSettingsView.qml`), which toggles each app through `MprisPlayers.setAllowed`.
* Weather block: the dashboard weather block (`windows/DashboardWeatherBlock.qml`) showing city, temperature, condition glyph, rain probability, and day high and low from `services/WeatherService.qml`. The source is Open-Meteo with no key, polled every 30 minutes and on dashboard open; a reading older than 60 minutes or a failed poll marks the city label stale while the last values stay. The last good payload caches at `weather.json` (setup in `docs/user/weather.md`).
* City search: the Settings Weather section (`windows/WeatherSettingsView.qml`) that searches the Open-Meteo geocoding API and writes the picked city to `weather-location`. Searchable under the `City` and `Location` labels; selecting a result repolls at once.
* Theme: an omarchy v4 (`quattro`) theme directory installed under the theme root. Its `colors.toml` is the palette and its `backgrounds/` directory holds images. Read as data, never executed (ADR 0010, ADR 0011).
* Palette: the color role set resolved from the active theme's `colors.toml` and mapped onto `config/Colors.qml` tokens. The word wallpaper is never used for this.
* Theme root: `~/.local/share/quickshell/themes`, the quickshell-owned directory the catalog scans and `qs-theme install` writes to. Not an omarchy path.
* Bundled theme: the one theme the repository ships, `darknight`, under `assets/themes/`, seeded into the theme root by `scripts/install.sh`. It is the hardcoded `config/Colors.qml` fallback made a real theme, with two backgrounds, so the catalog is never empty on a fresh install.
* Default theme: `ThemeService.defaultThemeName` (`darknight`), selected once the catalog is ready when the state file holds no saved selection; a state file that does not parse as a JSON object counts as no selection, so a corrupt file heals to the default. A selection the user saved, even one whose theme left the catalog, is not overridden.
* Catalog: the themes discovered in the theme root, listed by display name, each carrying a preview swatch strip read from its `colors.toml`. The scan, the parser, and the preview invariant are in `docs/dev/theme-catalog.md`.
* Background: an image a theme ships under its `backgrounds/` directory. The user picks one per theme; the choice is remembered per theme and applied with awww. A new pick queues behind the running awww rather than restarting it, so a superseded process's non-zero exit is not read as a failure.
* Surface: a `config/Colors.qml` role group (panel, card, border, text) derived from palette roles when the theme has no exact key for it.
* Theme switch: applying a catalog theme so the palette, the bar, the rendered desktop files, and the remembered background all change together. A fresh install selects the bundled darknight theme, so the default palette matching the hardcoded `config/Colors.qml` fallback is written only when the bundle is absent or a saved theme left the catalog, keeping the bar and the desktop files in agreement.
* qs-theme: the CLI (`install`, `remove`, `list`, `current`, `set`, `background`, `add-background`, `remove-background`), a thin client over shell IPC except that `install`, `remove`, `add-background`, and `remove-background` write the theme root themselves.
* Desktop retint: `scripts/render-theme.sh` substitutes the active palette into the repo-owned templates under `assets/templates/` and writes one file per target (Firefox contributes two: `chrome/shell-palette.css` and `user.js`). The apps are Hyprland borders (`~/.config/hypr/theme.lua`), kitty (`~/.config/kitty/theme.conf`), hyprlock (`~/.config/hypr/hyprlock/colors.conf`), starship (`~/.config/starship.toml`), yazi (`~/.config/yazi/theme.toml`), btop (`~/.config/btop/themes/theme.theme`), Firefox (the profile's `chrome/shell-palette.css` and `user.js`), Vencord (`~/.config/Vencord/themes/quickshell.theme.css`), and Spicetify (the bundled `text` theme, rendered to `~/.config/spicetify/Themes/quickshell/color.ini` and `user.css`). `ThemeService` runs it on every palette load and change through a `Process`, and passes the enabled target keys so a target the user switched off in the Themed apps section renders a no-op layer instead of a missing file. Borders honor the theme's `hyprland_*_border` keys when present and otherwise derive from `accent`. Starship and yazi have no include directive, so the renderer owns their whole config files (yazi's replaces the static flavor reference); btop is pointed at the rendered theme by a one-time pick in its options menu, which stores the absolute path the menu matches; the rest are wired in by user-added include, source, or `@import` lines (`docs/user/theme-desktop-setup.md`). The renderer writes a file only when the bytes change, and it never reads or evaluates a theme directory (ADR 0018).
* Themed app: an application the desktop retint writes output for. The set is fixed: Hyprland borders, kitty, hyprlock, starship, yazi, btop, Firefox chrome, Vencord, and Spicetify. Each app has a template, a render case, and an on/off flag, so it can be switched off on its own (ADR 0018).
* Spicetify theme: the bundled copy of the community `text` theme (MIT, vendored as templates under `assets/templates/`) that the renderer owns under `~/.config/spicetify/Themes/quickshell/`. The theme keeps its own default color options in `color.ini`, and the renderer appends one `Quickshell` color option built from the palette and refreshes the client with `spicetify refresh`. The user selects the theme and that color option once (ADR 0018).
* Themed apps section: the Settings section (`windows/ThemedAppsSettingsView.qml`) listing every themed app as a toggle. It edits `ThemeService`'s enable map, persisted to the `theme-targets` state file behind the `StateFile` load guard, and each app is searchable by its label.
* Firefox palette sheet: the generated `chrome/shell-palette.css` in the active Firefox profile, holding `:root` color variables the user's own `userChrome.css` imports. The renderer finds the profile through `installs.ini` and writes through the profile path, which psd syncs. Chrome only, no page content; the legacy-sheets pref lives in a generated `user.js`.
* Vencord recolor: the generated Vencord theme that overrides `system24`'s namespace variables on `:root` and leaves the base theme's layout in place. The user enables it once and lists it after `system24`. It depends on a system24/midnight-style base theme by design (ADR 0018).
* Polkit agent: the `services/PolkitService.qml` singleton, which owns one `PolkitAgent` and registers it for the shell session, plus the `windows/PolkitDialog.qml` B2 runner instantiated once in `shell.qml`. The dialog is modal (`WlrKeyboardFocus.Exclusive`), shows a message row for PAM errors and informational notices alike, and takes Enter to submit, Esc to cancel, Tab to cycle identities. The shell must be the only registered agent; the KDE agent is not autostarted. ADR 0015.
* Bar anchor: `services/BarAnchor.qml`, a small `QtObject` a bar-triggered panel service composes beside its `PanelState`. Its `register(item)` / `unregister(item)` hold the trigger item for the primary monitor's bar, and `requestToggle()` returns false when none is registered and otherwise re-emits `toggleRequested` so the module runs the same `Panels.toggleAt(...)` path a click uses. Power, Calendar, and Notification each expose theirs as `barAnchor`; the Cava panel has none because it has no bar toggle. ADR 0001 amendment (2026-10-08).
* IPC targets: the shell's callable entry points (`power`, `calendar`, `notifications`, `dashboard`, `dnd`, `volume`, plus `theme` and the opt-in `devprobe`), reached with `quickshell ipc call <target> <function> [args]`. Each is an `IpcHandler` on the service that owns its state; `quickshell ipc show` lists them. The user page is `docs/user/ipc.md`.
* Volume OSD: `windows/VolumeOsd.qml`, a click-through `PanelWindow` that shows a transient level bar bottom-center on the focused monitor whenever the default output's PipeWire volume or mute changes from any source. It holds for `Globals.osdHoldMs` (1400 ms) after the last change, captures the screen on the hidden-to-shown transition, and fades in `Globals.reducedMotion ? 0 : Globals.toastMs`. Settings → Audio ("Volume OSD") turns it off, persisted as `osdEnabled` in the `audio-outputs` state file and default on. ADR 0017.
